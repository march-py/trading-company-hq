# S00.2 — Local App, Environments & Secrets

## Application boundary

- The browser application is a React SPA built by Vite.
- The Cloudflare Worker handles `/api/*`; `GET /api/health` is the only S00.2 API.
- Unknown API routes return a JSON 404. All other routes are SPA assets/routes.
- No trading, broker, authentication, storage, or deployment behavior is in scope.

## Environments

| Context | Worker name | `APP_ENV` | Purpose |
| --- | --- | --- | --- |
| LOCAL/DEV | `trading-company-hq-dev` | `dev` | Development and local validation |
| PROD | `trading-company-hq-prod` | `prod` | Production build target only in S00.2 |

DEV and PROD have explicit, separate Wrangler environment entries. Configuration and secret bindings are not assumed to inherit across environments.

## Secrets

- S00.2 requires no secret values.
- If a later authorized stage adds a local secret, place it in ignored `.dev.vars.dev`; never mix `.dev.vars` and `.env` strategies.
- Use `config/dev.vars.dev.example` only as a name-only template.
- Production values must use Cloudflare secret storage, never repository files, documentation, logs, or client-side variables.
- `.dev.vars*` and `.env*` are ignored by Git.

## Private access

The intended external boundary is Cloudflare Access in front of the deployed application. S00.2 documents that boundary only. Access policy, identity-provider setup, account changes, and deployment belong to S00.3 and require separate authorization.

## Local commands

- `npm run dev`: integrated local SPA + Worker using DEV configuration.
- `npm run check`: generated bindings, typecheck, lint, tests, and both environment builds.
- `npm run build:dev` / `npm run build:prod`: explicit environment builds without deployment.
