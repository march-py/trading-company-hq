# S00.3 — DEV Deployment and Recovery

## Scope

Only the `dev` Wrangler environment may be deployed during S00.3. No command in this repository deploys PROD.

## Validation and deployment

1. Run `npm run check`.
2. Run `npm run deploy:dev:dry-run` and inspect the `APP_ENV=dev` and `trading-company-hq-dev` target.
3. Run `npm run deploy:dev` only after Cloudflare authentication and private-access readiness have been verified.
4. Record the deployed version ID and URL without recording credentials.

The deployment scripts rebuild DEV immediately before invoking Wrangler. This prevents a preceding PROD build from leaving a mismatched redirected deployment configuration in `dist/`.

## Recovery

1. List deployments with `npx wrangler deployments list --env dev`.
2. Inspect versions with `npx wrangler versions list --env dev`.
3. Roll back to the recorded known-good version with `npx wrangler rollback <VERSION_ID> --env dev --message "S00.3 recovery proof"`.
4. Recheck the deployed page and `/api/health` after rollback.

Rollback affects the remote DEV Worker immediately. It must not be run against PROD during S00.3.

## Access boundary

The DEV Worker must be placed behind an owner-only Cloudflare Access application before S00 can be closed as private. Access policy and authenticated/unauthenticated verification evidence belong in the S00.3 validation record; no identity or token values belong in source or reports.
