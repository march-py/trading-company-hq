# S01.2 — HQ Shell & Navigation

## Permanent frame

`AppShell` establishes the desktop application frame: a persistent sidebar and a stable content region. `PageScaffold` supplies the shared page heading, status, action, and content structure used by future HQ areas.

The Lobby is the default and only available destination in this chunk. Planned destinations are visible as stable module insertion points, grouped by operating purpose, and disabled until their owning stages are implemented.

## Navigation map

- **Headquarters:** Lobby (S01), Market data (S03).
- **Decision desks:** Research (S04–S06), Trading (S07–S10), Portfolio (S11–S13).
- **Control room:** Risk and oversight (S14–S15), Automation (S16–S17), System settings (S18).

The active destination exposes `aria-current="page"`; planned destinations use native disabled controls. Navigation remains local and dependency-free.

## Shared layout primitives

- `AppShell`: permanent sidebar and content frame.
- `Sidebar`: grouped active and planned navigation states.
- `PageScaffold`: reusable page header, controls, and content region.
- `PanelShell`: general grouped content surface.
- `CardShell`: compact summary surface.
- `TableShell`: accessible table container with shared heading treatment.

## Lobby

The Lobby demonstrates the permanent shell without introducing business data. It contains system posture, the interface-foundation release track, future module insertion points, and a structural build-sequence table.

## Stage boundary

This is a desktop-first shell. It does not include responsive or mobile rules, a command palette, an instrument drawer, generalized loading/error/empty-state components, business logic, live market data, trading integrations, or account configuration changes.
